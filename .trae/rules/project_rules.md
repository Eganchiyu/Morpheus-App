# Project Rules

本项目旨在构建一款帮助用户及时记录、回忆梦境并发现相关内容的移动应用，面向 iOS 与 Android。Version 0.1 聚焦本地优先的梦境记录、提醒、编辑删除与日历回顾；未来可能加入手表睡眠数据、AI 画报、AI 周期总结、内容推荐与云端同步。

请保持简短而直击重点的输出，不要过于复杂，只完成要做的事情就收手。尽快完成任务不拖沓。

如果需要机主介入进行操作（如获取sudo密码或安装操作），请结束任务并告知，等待完成后继续任务。

规格书指引文档：[`docs/Document.md`](docs/Document.md)

执行代码期间，需在关键节点提交 git 进行版本控制，并在 `docs/Log.md` 中书写简短开发日志。

#### 1. 核心原则

- 本地优先，隐私优先：梦境数据默认保存在设备本地，上传或 AI 分析必须经用户明确授权。
- 所有功能必须可通过配置开启、关闭或替换，禁止写死无法关闭的行为。
- 平台差异通过抽象接口处理，iOS 与 Android 行为尽量一致。
- 技术栈确定后全项目统一，不得混用 Flutter 与 React Native。
- 任何涉及健康数据、通知、AI 的功能，必须提供降级方案，确保无权限时仍可使用核心记录功能。

## 2. 代码与架构

- 使用确定后的技术栈（Flutter 或 React Native）及对应语言标准，构建系统统一。
- 公共接口以 `I` 开头（如 `IDreamRepository`），实现类使用明确后缀（如 `LocalDreamRepository`）。
- 禁止跨层直接调用具体实现，必须通过接口或状态管理层通信。
- UI 线程禁止阻塞操作；耗时任务（如 AI 调用、数据导出）放入独立线程或异步任务。
- 所有资源（数据库、文件、网络连接）遵循 RAII 或对应生命周期管理，禁止泄漏。
- 新增输入源、存储后端、AI 服务时，只扩展接口实现，不修改核心业务逻辑。

## 3. 配置与数据

- 配置文件使用 YAML 或 JSON，顶层键固定为 `global`、`notifications`、`health`、`ai`、`output`、`privacy`。
- 用户设置必须显式声明：提醒时间、权限状态、AI 开关、数据导出路径等。
- 数据结构必须与 Cubism 无关；梦境记录字段固定，扩展字段通过可选键添加。
- 启动时校验配置与权限，无效项需报告并回退到安全默认值。
- 支持配置热重载（至少设置项），重载不得丢失未保存的梦境草稿。
- 禁止在版本库中提交用户梦境数据、健康数据、密钥或生成物。

## 4. 协作与提交

- 提交信息使用 `类型: 简短描述`，类型限定为 `feat`、`fix`、`refactor`、`docs`、`chore`。
- 每次提交只做一件事，禁止混合功能与格式化。
- 提交时同步更新 `CHANGELOG.md`，记录最近变更。
- 修改公共接口、数据结构或配置结构时，必须同步更新 `docs/` 下对应说明。
- 新增依赖需在 `README` 或 `docs/deps.md` 中记录用途与安装方式。
- 长期分支保持可编译、可运行；实验性改动放入独立分支，合并前清理临时代码。
- Version 0.1 严格只做核心闭环：提醒、记录、编辑删除、日历回顾、本地保存；AI 与云同步后置。
